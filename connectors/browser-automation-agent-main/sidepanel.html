Agent behavior

These shape how the agent works through automation runs — worth tuning to your model and how much autonomy you want.

Tab sharing

Put tabs into a tab group named Assistant to share them with the agent. A run started from a grouped tab sees and acts on only those tabs — and can read them together for cross-tab tasks (compare, summarize, extract). Drag a tab out of the group to revoke access instantly; the tab bar always shows exactly what's shared.

Site permissions

Restrict which sites the agent may act on. A host also matches its subdomains (google.com covers mail.google.com). Leave on “All sites” to allow everything. Allowlist runs only on the listed hosts; blocklist runs everywhere except them. Blocked runs are stopped before they start, and mid-run navigations to a disallowed host are refused.

Site memory

When enabled for a site, selector fixes the LLM finds during runs are remembered and retried automatically on future visits — no extra LLM call. Notes are shown to the planner whenever it works on that site.

    Secrets

    redacted in output

    Store sensitive values (passwords, tokens) once and reference them by name in your steps as ${secrets.password}. Values are substituted at execution time and never echoed back.

    1. Configure
    Enter a JSON object of name/value pairs: 
    {
  "username": "qa@example.com",
  "password": "S3cr3t!"
}
    2. Use
    Reference any key as ${secrets.<name>}. It works the same in a plain-English instruction or in a test file step: 
    # in a typed instruction
Log in with ${secrets.username} and ${secrets.password}

# in a test file step
- action: type
  selector: "#password"
  value: "${secrets.password}"

      Backup & restore

      Settings, shortcuts, and site memory are mirrored to your Chrome profile and restored automatically after a reinstall — when you're signed into Chrome with extension sync on. Your API key and secrets vault are never included in that automatic sync; Export below is the only way to back them up, and it writes them as plaintext to a local file.

      Modes

      pick one in the composer

      The mode dropdown next to the message box controls how AiNxt handles your request. Start with auto and switch only when you want explicit control.

      auto
      Handles everything: clear questions are answered in chat, and page work is planned and run from your plain-English instruction. Risky steps (purchases, deletions, submits) automatically pause for your approval.
      test
      Runs a structured JSON/YAML test file — attach one with the + button or record one with ●.
      ask
      Chat with the AI without touching the page.
      debug
      Watches console & network errors and explains the root cause.

      Recording

      the ● button

      In test mode, click ● in the composer, then interact with the page — clicks and typing are captured (the badge counts steps). Click ● again to stop, and the recording is turned into a replayable YAML test file you can run in test mode. If the test file already has steps, you'll be asked to append or replace.

      Scheduled prompts

      saved prompts, on a timer

      Agent behavior

      in Settings

      These shape how the agent works through automation runs — worth tuning to your model and how much autonomy you want.

      Agent loop
      Decide one action at a time against fresh page state, instead of planning the whole run up front. Best for exploring unfamiliar pages.
      Vision
      Attaches a page screenshot each turn so the agent can see the page. Needs a multimodal model (GPT-4o, Claude, Gemini).
      Max steps per run
      Action budget for agent-loop runs (5–100). Exhausting it ends the run with status max_steps_reached, not a failure.
      Stream narration
      Types out the agent's reasoning token-by-token. Off by default for servers that don't support SSE streaming.
      Auto-approve
      Skips the approval prompt and lets risky steps (navigation, submits, uploads) run unattended. Use with caution.
      Ask before acting
      Drafts a plan for automation runs and shows it for review before AiNxt touches the page. Edit steps inline, ask AiNxt to redraft with Update plan, preview targets with Dry run, then approve.
      Step-by-step
      Pauses before every action and waits for Continue, showing what the previous step did. Full manual oversight; Auto-approve does not skip these pauses.
      Record GIF
      Captures a screenshot per action and offers an animated GIF of the run for download (adds a screenshot per step, capped at 60 frames).
