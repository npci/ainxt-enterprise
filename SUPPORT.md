# Support

## Read this first

**Contributions and issue triage are not open yet.** AiNxt Enterprise is published under
the MIT License as source-available software. You may use, modify and redistribute it under the
licence, but external issues and pull requests are **not currently accepted or triaged**,
and no commitment is made to review or respond to them. See
[`CONTRIBUTING.md`](CONTRIBUTING.md) for the full posture.

That means: for general questions, the documentation in this repository is the support
channel. Please set expectations accordingly before filing anything.

## Where to look for answers

| Question | Where to look |
|---|---|
| How do I install and run the platform? | [`README.md`](README.md) — Prerequisites and Quick Start |
| What does a configuration variable do? | [`.env.example`](.env.example) — every variable is documented inline |
| How do I point it at a model provider? | [`README.md`](README.md) — LLM Configuration |
| How does a specific module work? | `docs/` — per-module reference pages |
| How is the project licensed? | [`LICENSE`](LICENSE), [`NOTICE`](NOTICE) |
| Who is accountable for this repository? | [`MAINTAINERS.md`](MAINTAINERS.md) |

## Security vulnerabilities — always in scope

Security reports are the **exception** to the posture above and are accepted at any time.

**Do not open a public issue for a vulnerability.** Use a
[private GitHub Security Advisory](../../security/advisories/new), as described in
[`SECURITY.md`](SECURITY.md).

## Contact

`opensource@npci.org.in` — the NPCI Open Source Programme group address, per
[`MAINTAINERS.md`](MAINTAINERS.md). It is a monitored group address rather than an
individual mailbox. Expect no service-level commitment for general support questions
while contributions remain closed.

## Reporting a documentation problem

If something in this repository is wrong, missing, or cannot be followed from a clean
machine, that is worth recording even while triage is closed — setup defects are the
hardest class of bug for a project to see from the inside. Note the file, the step you
were on, and what actually happened.
