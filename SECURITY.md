# Security Policy

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

We use **GitHub Security Advisories** for responsible
disclosure. This keeps the report private until a fix is ready and gives you credit
for the discovery.

### How to Report

1. Go to the **Security** tab of this repository.
2. Click **"Report a vulnerability"** — or go straight to
   [`../../security/advisories/new`](../../security/advisories/new).
3. Fill in the advisory form with as much detail as possible.

The report stays confidential between you and the maintainers until a fix is
published, and GitHub handles CVE assignment if one is warranted.

> **No email alias is published for this project.** An address that silently
> bounces is worse than no address at all, so none is listed here. If a monitored
> security alias is stood up later it will be added to this file.

---

## What to Include

A good vulnerability report includes:

- **Description** — what the vulnerability is and its potential impact.
- **Steps to reproduce** — a minimal, reliable reproduction path.
- **Affected component** — which service, file, or endpoint is affected.
- **Suggested fix** — optional, but appreciated.
- **Your contact details** — so we can keep you updated and credit you.
