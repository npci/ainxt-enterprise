# PyTorch's CPU-only wheel index. This platform does not use GPU/CUDA
# acceleration. On Linux (this platform's Docker/deployment target),
# `docling` (below) transitively pulls the default GPU wheel of torch,
# which depends on NVIDIA's proprietary-licensed cuda-bindings/cuda-toolkit/
# nvidia-*-cu13 packages (torch's Requires-Dist entries for these are gated
# by `platform_system == "Linux"` — confirmed via wheel METADATA). The
# Linux-only pin below avoids that. Windows/macOS installs (local dev) never
# pulled those NVIDIA packages in the first place, since the same platform
# marker excludes them there — so no pin is needed or applied on those
# platforms; `docling`'s own torch requirement resolves normally. See
# THIRD-PARTY-NOTICES.md §1.5b.
--extra-index-url https://download.pytorch.org/whl/cpu

# ── ABStudio OCR pipeline (app/core/ocr_pipeline.py) ─────────
# Powers attachment uploads on the Workflow chat, Agent chat, and KB
# upload flows. Each lib is wrapped in `try / except ImportError` in
# the pipeline so a missing optional dep degrades to a warning rather
# than a hard failure.

# pdfplumber — Pass 2a: pipe-table extraction from born-digital PDFs.

# camelot-py — Pass 2b/2c: lattice + stream table extraction for unstructured
# PDFs (forms, bank statements, invoices). Renders via pypdfium2, so NO
# Ghostscript / poppler system packages are required. (The `[base]` extra was
# dropped upstream in camelot-py 1.0.0 and is a no-op warning on anything this
# range resolves to; it never pulled PyMuPDF, contrary to an earlier note here.)

# Pillow — image normalization (EXIF orient, RGB convert, deskew) for
# standalone PNG/JPG/TIFF/BMP/WEBP uploads. Already pinned above
# (pillow==12.3.0).
# Page rasterisation and embedded-image extraction for core.pdf_ocr go through
# core.pdf_backend (page.get_pixmap / page.get_images / doc.extract_image), so
# they follow PDF_BACKEND and need no engine pinned here beyond pypdfium2.
# rapidocr-onnxruntime — local ONNX OCR engine. Used for scanned PDFs,
# embedded raster images, and standalone image uploads. CPU-only,
# no GPU required.

# ── PaddleOCR — NOT installed by default ────────────────────────
# Moved to requirements-ocr.txt. It is a genuinely optional second OCR engine:
# rapidocr-onnxruntime above already handles scanned PDFs, embedded images and
# image uploads on CPU, and every paddle import in this codebase is lazy and
# guarded (core/paddle_ocr_model.py, core/paddle_ocr_subprocess.py), so the
# platform boots and does OCR without it.
#
# Why it is not here: paddlepaddle adds ~353 MB, and the unpinned range made pip
# backtrack through 55 paddle* versions — over 20 minutes on a cold install —
# because newer paddleocr 3.x pulls the paddlex tree.
#
# To enable it:
#     Docker  ./install.sh --with-ocr
#             (or WITH_OCR=1 docker compose up -d --build gateway)
#     Native  pip install -r requirements-ocr.txt
